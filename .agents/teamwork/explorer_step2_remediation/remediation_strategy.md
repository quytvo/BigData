### 1.2 Downstream Data Duplication Impact
When data consumers (such as PyArrow, Pandas, or Spark itself) scan `lakehouse_storage/silver/tedp_station/`:
- PyArrow parses both `province_name=Gia%20Lai` and `province_name=Gia Lai` as partition key `province_name == "Gia Lai"`.
- Total row count inflated from the true **440,012 genuine records** to **549,100 records** (109,088 duplicate records).
- All measurements for four provinces (`Gia Lai`, `Lâm Đồng`, `Tây Ninh`, `Đà Nẵng`) are loaded twice.

### 1.3 Empirical Root Cause Verification
Our live controlled experiments across both execution environments isolated the exact mechanism:
1. **Windows Host Execution**:
   - PySpark on Windows (running with `winutils.exe` / Hadoop `RawLocalFileSystem`) converts directory paths through URI serialization.
   - Partition names containing spaces are URL-encoded (`%20`): e.g., `province_name=Gia%20Lai`, `province_name=Bắc%20Ninh`.
2. **Linux Docker Container Execution (`airquality-spark:3.5.1`)**:
   - PySpark 3.5.1 on Linux POSIX filesystem writes partition directory names with literal spaces: e.g., `province_name=Gia Lai`, `province_name=Bắc Ninh`.
3. **The Spark Overwrite Flaw**:
   - `code/lakehouse/spark_preprocess_tedp.py` and `code/lakehouse/spark_sync_province.py` rely exclusively on:
     ```python
     df.write.mode("overwrite").partitionBy("province_name").parquet(output_dir)
     ```
   - In Apache Spark, overwriting a partitioned dataset does **NOT** perform a directory wipe (`rm -rf output_dir`). Instead, Spark's internal `InsertIntoHadoopFsRelationCommand` only deletes subdirectories whose string paths match the partition specs generated by the *current active JVM*.
   - To the OS filesystem (NTFS on Windows and ext4/overlayfs on Linux), `'province_name=Gia Lai'` (ASCII 32) and `'province_name=Gia%20Lai'` (ASCII 37, 50, 48) are two distinct directories.
   - When the pipeline was executed across both environments (or when Docker ran after a Windows run), Spark overwrote its own format and left the foreign platform's directories untouched, resulting in 15 partition directories on disk.

## 2. Destination Directory Cleanup Strategy

### 2.1 The Architectural Requirement
Prior to invoking Spark's `DataFrameWriter.write.parquet(...)`, the pipeline must guarantee that the target directory is completely purged of any prior state. This satisfies the **Idempotency Guarantee** required by Lakehouse storage:
$$f(\text{Dataset}) = f(f(\text{Dataset}))$$
Regardless of whether the previous execution occurred on Windows host, in Docker, or aborted halfway through a partition write, the resulting storage state must be identical, deterministic, and contain exactly the 11 expected partitions.

### 2.2 Cleanup Method Analysis
| Method | Feasibility | Cross-Platform Safety | Verdict |
|---|---|---|---|
| **A. Reliance on Spark `.mode("overwrite")`** | Low | Fails when partition path encodings diverge (%20 vs space). Leaves stale partitions. | **REJECTED (Current bug)** |
| **B. Hadoop FileSystem Java API (`fs.delete(path, true)`)** | Medium | Requires active JVM and Py4J call. Prone to Winutils permission errors on Windows host. | **REJECTED (Unnecessary complexity)** |
| **C. Python-Level Deterministic Purge (`purge_output_directory`)** | High | Native Python `shutil.rmtree` runs in driver process before Spark write. Completely deletes target folder. Handles Windows file permissions and retries. | **ADOPTED (Standard Best Practice)** |

### 2.3 Robust Implementation Specification: `purge_output_directory`
To guarantee cross-platform reliability on both Windows 11 NTFS and Linux Docker container, the cleanup function must handle:
1. Missing directory: No-op if directory does not exist.
2. Windows read-only file locks: Automatically reset file attributes (`stat.S_IWRITE`) on permission error.
3. Transient lock retry: Retry up to 3 times with 0.5s backoff if Windows OS holds an indexing or anti-virus handle.
4. Fail-fast error escalation: Raise `RuntimeError` if directory cannot be cleanly purged, preventing silent corruption.

```python
def purge_output_directory(target_dir: Path) -> None:
    """Safely and deterministically purges a target directory prior to writing partitioned Parquet.

    Prevents cross-platform partition collisions (%20 vs literal space) and
    stale partition accumulation across Windows host and Linux Docker container.
    """
    if not target_dir.exists():
        return

    logger.info("Purging target directory prior to write: %s", target_dir)
    import os
    import shutil
    import stat
    import time

    def _handle_readonly(func, path, exc_info):
        try:
            os.chmod(path, stat.S_IWRITE)
            func(path)
        except Exception as err:
            logger.warning("Failed to reset permissions on %s: %s", path, err)

    for attempt in range(3):
        try:
            shutil.rmtree(str(target_dir), onerror=_handle_readonly)
            logger.info("Successfully purged directory: %s", target_dir)
            return
        except Exception as exc:
            logger.warning("Purge attempt %d for %s failed: %s", attempt + 1, target_dir, exc)
            time.sleep(0.5)

    if target_dir.exists():
        raise RuntimeError(f"Failed to cleanly purge target directory: {target_dir}")
```
